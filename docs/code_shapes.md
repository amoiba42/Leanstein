# Code shapes: before/after cases from the study

15 real cases from the confirmatory study `main`, generated by `scripts/code_shapes_catalogue.py` from `runs/main/` (nothing is edited by hand). Each is a run of **C** that was verified although the family's *reference* implementation is **not** provable by the frozen portfolio, so the verified code had to take a different, automation-friendly shape. On the same instance and seed, **B** (the model writes code and proof, with feedback) failed. For each case: the injected bug, the reference, C's verified code, the portfolio entry that closed the locked theorem, and what B did. `{F}`, `{P}`, `{Q}`, `{H}` in a tactic are filled with the function, precondition, postcondition and helper names.

Patterns. In 9 of the 15 cases C's code drops the reference's recursion, usually also its `match` and `if`, and states the result with library combinators (`filter`, `all`, `foldl`, `count`, `List.range`) that `simp`, `omega` and `grind` already handle. The B→C cross-evaluation (`results/crosseval.md`) measures the second case over all runs.
