### **Benchmark, Execution & Infrastructure**

* **Generate Real Errors First:** Run Qwen models on benchmark problems in a zero-shot setting (without examples or hints). Collect the actual incorrect `.lean` files they produce and use those authentic failure cases as inputs to evaluate the code-repair pipeline instead of relying on synthetic mutations.
* **Track Energy Consumption (Green AI):** Supplement model call counts by measuring true hardware resource usage. Integrate tools like `codecarbon` or `pyJoules` to log CPU/GPU energy usage and carbon emissions directly into the JSONL output logs.
* **Prevent Memory Crashes via Sandboxing:** Enforce execution safety using Python’s `resource.setrlimit` or Linux’s `systemd-run` to cap individual process memory at 2 GB RAM alongside strict execution timeouts, preventing system crashes during heavy tactic execution.
* **Separate Infrastructure Failures:** Introduce a dedicated handling pathway for infrastructure crashes (memory limits, timeouts, process failures). Route these to trigger an immediate environment rerun without burning the model’s fix retry budget.
* **Track Total Execution Time:** Update the central logging system to record both `model_secs` (LLM generation overhead) and `lean_secs` (formal verification overhead) to capture the total compute cost per repair attempt.
* **Log Every Repair Attempt:** Log all verification attempts—including intermediate failures—to JSONL before proceeding to subsequent retries, capturing `attempt_idx`, specific failure types, and execution times for granular post-hoc analysis.

### **Tactic & Feedback Routing**

* **Adaptive Tactic Router (C-only):** Avoid executing all Lean tactics uniformly across every instance. Implement an adaptive routing strategy that runs lightweight tactics first (`simp`, `omega`, `decide`) with a short 2-second timeout, falling back to heavy search tactics (`aesop`, `grind`) only when simpler ones fail to close the goal.
* **Dedicated Multi-Path Feedback Router:** Replace the single general-purpose hint extractor with a specialized router that categorizes failure modes (integrity violations, concrete test failures, unclosed proof goals) and returns tailored diagnostic feedback for each type.
* **Keep Hidden Tests Private:** Configure the feedback router so failures on hidden test cases return only a generic status warning, ensuring hidden test inputs and expected outputs are never leaked into the model context.
* **Simple Retry Baseline ($C_{\text{plain}}$):** Add a baseline control variant where the model receives only a non-informative failure notification ("failed, retry") upon error, establishing a clear benchmark to quantify the value of detailed diagnostic feedback.

### **Integrity, Guardrails & Auditing**

* **Automated Cheating Detection (Spec-Gaming Audit):** Implement a Python-based AST parser or regex pre-check to catch specification gaming (such as removing required assertions, leaving function bodies empty, or outputting trivial truths) prior to invoking Lean verification.
* **Manual Success Audit:** Route verified successful repairs through a post-processing pipeline that randomly selects 10% of cases for human inspection to ensure automated verification wasn't bypassed.
* **Maximum Resampling Cap:** Enforce a strict `resample_cap` during initial mutant/error generation phases. If the generation attempt limit is reached, automatically skip the task to prevent pipeline loops.
